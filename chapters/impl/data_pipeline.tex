\section{Структура данных и пайплайн подготовки датасета}
\label{sec:data-structure-pipeline-preprocessing}

\subsection{Структура данных}

Исходный датасет, предоставленный Заказчиком, представляет собой иерархическую файловую систему, в которой каждая трёхмерная модель с историей построения хранится в отдельной папке. Общий корень датасета содержит вложенные каталоги произвольной глубины, однако на самом нижнем уровне (далее — «листовые папки») располагаются файлы, относящиеся к одной модели.

\subsubsection{Файловая организация листовой папки}

Каждая листовая папка в исходном датасете содержит три типа файлов:

\begin{itemize}
    \item \textbf{Один JSON-файл} (расширение \texttt{.json}) — описание истории построения модели в структурированном виде. Имя файла может быть произвольным, но в папке присутствует ровно один такой файл.
    \item \textbf{Несколько STL-файлов} (расширение \texttt{.stl}) — триангулированные сетки, соответствующие различным шагам построения модели. Каждый STL-файл именуется по шаблону, содержащему индекс шага (например, \texttt{index0.stl}, \texttt{index1.stl}, \dots).
    \item \textbf{Несколько STEP-файлов} (расширение \texttt{.stp}) — точные B-Rep представления геометрии на тех же шагах построения. Количество STEP-файлов всегда совпадает с количеством STL-файлов, а имена содержат те же индексы (например, \texttt{index0.stp}, \texttt{index1.stp}, \dots).
\end{itemize}

Таким образом, каждая пара \texttt{indexN.stl} и \texttt{indexN.stp} соответствует одному и тому же шагу построения (состоянию модели после выполнения очередной операции). Индексы идут подряд, начиная с 0, но не обязательно являются строго последовательными без пропусков. Минимальное количество шагов в исходном датасете — два (начальное состояние и состояние после одной операции), однако в большинстве папок присутствует большее число шагов.

\subsubsection{Структура JSON-файла истории}

JSON-файл описывает всю последовательность формообразующих операций, которые были применены к модели. Основные поля:

\begin{itemize}
    \item \texttt{"entities"} — словарь, в котором каждый ключ (идентификатор сущности) ссылается на объект, описывающий либо операцию, либо эскиз, либо вспомогательную геометрию. Каждая сущность содержит поле \texttt{"feature"}, определяющее тип операции (например, \texttt{"o3d\_sketch"} для эскиза, \texttt{"bossExtrusion"}, \texttt{"cutExtrusion"}, \texttt{"fillet"}, \texttt{"chamfer"} и т.д.).
    
    \item \texttt{"sequence"} — список шагов построения в хронологическом порядке. Каждый элемент списка представляет собой словарь с полем \texttt{"entity"}, содержащим идентификатор сущности из \texttt{entities}. Порядок элементов в \texttt{"sequence"} соответствует последовательности применения операций.
    
    \item Для операций выдавливания и вырезания в сущности может присутствовать вложенный объект \texttt{"sketch"} или \texttt{"profile"}, которые содержат ссылку (\texttt{"ref\_entity\_index"}) на сущность эскиза. Эскиз, в свою очередь, содержит массив \texttt{"sketch\_objs"}, где каждый объект описывает геометрический примитив (отрезок, дугу, окружность) с указанием его типа (\texttt{"type"} = \texttt{"line"}, \texttt{"arc"}, \texttt{"circle"} и т.д.).
\end{itemize}

Пример фрагмента JSON (гипотетический):
\begin{verbatim}
{
  "entities": {
    "ent1": { "feature": "o3d_sketch", "sketch_objs": [{"type": "line"}, ...] },
    "ent2": { "feature": "bossExtrusion", "sketch": {"ref_entity_index": "ent1"} }
  },
  "sequence": [
    { "entity": "ent1" },
    { "entity": "ent2" }
  ]
}
\end{verbatim}

Важно отметить, что JSON-файл не содержит прямой привязки к именам STL/STEP-файлов. Соответствие между шагами в \texttt{"sequence"} и файлами с индексами устанавливается по порядку: первый шаг последовательности соответствует \texttt{index0.stl}/\texttt{index0.stp}, второй — \texttt{index1.stl}/\texttt{index1.stp} и т.д. Таким образом, для восстановления истории построения необходимо синхронизировать временную ось, заданную JSON, с набором пронумерованных геометрических файлов.

\subsubsection{Критерии пригодности папки для использования}

В рамках настоящего исследования листовая папка считается пригодной для дальнейшей обработки, если выполняются следующие условия (реализованные в функции \texttt{find\_innermost\_folders} скрипта подготовки данных):

\begin{enumerate}
    \item В папке присутствует ровно один JSON-файл.
    \item Количество STL-файлов равно количеству STEP-файлов.
    \item Количество STL-файлов не менее заданного порога (в данной работе — не менее 2, чтобы иметь как минимум начальное и конечное состояние).
    \item Отсутствуют другие папки-потомки (т.е. папка является листовой в иерархии).
\end{enumerate}

Папки, не удовлетворяющие этим критериям, отбраковываются на этапе предобработки, а их статистика фиксируется для контроля качества датасета (см. раздел \ref{sec:data-pipeline}).

Такая организация данных позволила автоматизировать процесс извлечения истории построения и разметки рёбер для обучения нейросетевых моделей без ручного вмешательства.

\subsection{Формирование и очистка обучающей выборки}
Исходный массив содержал 82~418 моделей, распределённых по папкам. Для каждой модели требовалось наличие как минимум двух последовательных шагов (начальная и конечная геометрия) и JSON-файла с описанием операции перехода. Процесс очистки включал следующие шаги:

\begin{enumerate}
    \item Удаление папок, в которых отсутствует JSON-файл (262 модели).
    \item Удаление моделей, у которых нет ни STL, ни STEP (7~417 моделей).
    \item Отбраковка моделей с единственной парой STL+STEP (нет соседних шагов) - 15~020 моделей.
    \item Ручная проверка аномалий: два JSON в одной папке (18 случаев), пустые STL, нечитаемые STEP.
\end{enumerate}

\subsection{Нормализация и препроцессинг}
Для каждого STL-файла, попадающего в обучение или инференс, выполняются следующие операции:
\begin{itemize}
    \item \textbf{Центрирование}: все вершины сдвигаются так, чтобы центроид модели оказался в начале координат.
    \item \textbf{Масштабирование}: модель масштабируется к единичному размеру (максимальная координата становится равной 1).
    \item \textbf{Приведение числа рёбер}: с помощью процедур subdivision/decimation количество рёбер фиксируется на значении 2250 (требование MeshCNN).
    \item \textbf{Удаление вырожденных граней}: треугольники с нулевой площадью или слишком острыми углами исключаются.
\end{itemize}

Параметры операций (глубина, радиус, угол) также нормализуются: для каждого параметра вычисляется среднее и стандартное отклонение по обучающей выборке, после чего применяется z-нормировка.

\subsection{Автоматическая разметка датасета}
Разметка рёбер для задачи сегментации выполняется автоматически на основе JSON-описания и STEP-файлов соседних шагов. Алгоритм:
\begin{enumerate}
    \item Для пары соседних шагов (до операции и после операции) загружаются STEP-модели.
    \item Вычисляются грани, которые изменились (добавлены, удалены, модифицированы).
    \item По JSON определяется тип операции, породившей изменение.
    \item Для каждого треугольника в финальной STL-сетке определяется, принадлежит ли он изменённой грани; если да, то все рёбра этого треугольника получают метку, соответствующую типу операции.
    \item Результат сохраняется в формате Colored OBJ, где рёбра кодируются тройками (индекс вершины 1, индекс вершины 2, метка класса).
\end{enumerate}
Такой подход позволяет получить размеченный датасет без ручной аннотации, однако он чувствителен к качеству сравнения STEP-моделей и может вносить ошибки при сложных топологических изменениях.
